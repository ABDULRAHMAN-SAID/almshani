# عقد التصنيف — تصنيف مستقلّ لكل لعبة

> نواة المرحلة ٢. بيانات ومنطق فقط: **لا ترسم شيئًا ولا تغيّر أي شاشة**.
> ربط نهايات المباريات بها هو المرحلة ٣.

---

## ١. المبدأ

مهارة الكيرم ليست مهارة المعرفة. فلكل لعبة **ملفّ تصنيف مستقلّ**، ولكلٍّ **نموذج حساب** يناسب طبيعتها، و**موسم واحد** يجمعها كلّها.

اللاعب قد يكون أسطوريًّا في المعرفة، ذهبيًّا في الكيرم، فضيًّا في أونو، برونزيًّا في مافيا — وهذا طبيعي ومقصود.

---

## ٢. الألعاب

معرّفات إنجليزية — الاسم العربي لا يُستخدم مفتاحًا للتخزين.

| المعرّف | الاسم | مفتاح الغرفة | نموذج الحساب | لاعبون |
|---|---|---|---|---|
| `knowledge` | عالم المعرفة | — | `winLoss` | 2 |
| `carrom` | كيرم | `carrom` | `winLoss` | 2–4 |
| `uno` | أونو | `uno` | `placement` | 2–4 |
| `mafia` | مافيا | `mafia` | `teamResult` | 5–12 |
| `drawing` | مسابقة الرسم | `draw` | `placement` | 3–10 |
| `outsider` | برا السالفة | `barra` | `roundsAggregate` | 3–8 |

كل لعبة في `GAME_DEFS` تحمل: `ranked` · `casual` · `room` · `bot` · `pass` · `minP` · `maxP` · `status` (`live` · `soon` · `maintenance`). **إضافة لعبة جديدة لا تتطلّب تعديل شاشة اللعب** — تُضاف صفًّا في الجدول.

---

## ٣. ملفّ التصنيف

```js
newRankProfile(gameId) → {
  gameId, seasonId,
  placed, placementDone, placementWins,
  tier, div, rp, mmr, protect,
  seasonBest:{tier,div},
  wins, losses, gamesPlayed, winStreak, bestStreak,
  masteryXp, lastPlayedAt, seen:[]
}
S.gameRanks = { knowledge, carrom, uno, mafia, drawing, outsider }
```

### مطابقة أسماء المواصفة

المواصفة (البند ٦٨) تسمّي الحقول بأسماء أخرى. الأسماء الداخلية بقيت كما كانت لأنّ **٤٤ موضع نداء قائمًا** يعتمد عليها، وتغييرها الآن انحدارٌ بلا فائدة للاعب. والدالة `rankView(p)` تُعيد شكل المواصفة حرفيًّا للواجهة والتوثيق:

| المواصفة | الحقل الداخلي |
|---|---|
| `visibleTier` | `tier` |
| `division` | `div` |
| `rankPoints` | `rp` |
| `hiddenMMR` | `mmr` |
| `peakTier` · `peakDivision` | `seasonBest.tier` · `seasonBest.div` |
| `placementMatchesRemaining` | `5 − placementDone` |
| `masteryLevel` | مشتقّ من `masteryXp` |

---

## ٤. `S.ranked` لم تُحذف — صارت اسمًا

`S.ranked` معرَّفة الآن **خاصيّة وصول غير مُعدَّدة** على الحالة:

* **القراءة** تعيد `S.gameRanks.knowledge` نفسه — لا نسخة.
* **الكتابة** تُرحِّل القيمة إلى ملفّ المعرفة.
* **غير مُعدَّدة** ⟵ `saveState` يستعمل `Object.keys(S)` فلا تُحفظ نسخةً ثانية.

فبقيت مواضع النداء الأربعة والأربعون تعمل كما هي، والبيانات في المصدر الجديد.

---

## ٥. الترحيل

رتبة اليوم كانت رتبة المعرفة فعليًّا، فتنتقل كما هي. وباقي الألعاب تبدأ **«غير مصنّف»** لا برونزي (البند ٩٢).

```js
loadState():
  const legacyRank = d.s.ranked; delete d.s.ranked;   // نسخة قديمة
  Object.assign(S, d.s);
  bindLegacyRanked();
  migrateRanks(legacyRank);
```

مفحوص من طرف إلى طرف في `tools/test-rank-persist.cjs`: حفظٌ بالصيغة القديمة ⟵ إعادة تحميل ⟵ الرتبة في مكانها، والباقي غير مصنّف، والحفظ الجديد لا يكرّر `ranked`.

---

## ٦. الأوضاع — من يمنح ومن لا يمنح

```js
function grantsRP(mode){ return mode === 'ranked' }
```

**نقطة واحدة في المشروع كلّه.** الغرفة بكود · ضد الكمبيوتر · اللعب العادي · تمرير الجوال · التدريب ⟵ **لا نقاط تصنيف إطلاقًا**، حتى لا يصنع أحد حسابين ويجمع رتبة (البند ١٥ و٧٧). وتُمنَح خبرة إتقان بدلها:

| الوضع | خبرة الإتقان |
|---|---|
| مصنّف | 12 |
| عادي | 7 |
| غرفة · تمرير | 5 |
| كمبيوتر | 3 |
| تدريب | 2 |

**الإتقان يعكس الوقت والإنجاز، والرتبة تعكس المهارة — ولا يُخلطان** (البند ٥٧).

---

## ٧. نماذج الحساب

كلّها تمرّ عبر واجهة واحدة:

```js
resolveMatch({gameId, mode, matchId, result, opponents})
 → {applied, rp, mmr, promoted, demoted, protected, placement, mastery, oldName, newName, reason}
```

| النموذج | شكل `result` | القاعدة |
|---|---|---|
| `winLoss` | `{won}` | فوز/خسارة + فرق المهارة. الإحصاءات الدقيقة (الدقّة · الأخطاء · الملكة) **للملفّ لا للنقاط** |
| `placement` | `{place, total}` | الأول ‎+24 تقريبًا والأخير ‎−20، والوسط بينهما |
| `teamResult` | `{teamWon, completed, left}` | نتيجة الفريق أساسًا · **الانسحاب يضرّ ولو فاز فريقك** · بلا أي تقييم للكلام |
| `roundsAggregate` | `{roundsWon, rounds}` | تُجمع الجولات ثمّ **نتيجة واحدة للمباراة** — لا نقطة لكل جولة |

النقاط من قوّة النتيجة وفرق المهارة:

```js
base = round(-20 + strength * 44)        // +24 للأول · −20 للأخير
adj  = clamp((oppMmr - myMmr)/150, -1, 1) * (base >= 0 ? 4 : -4)
rp   = clamp(base + adj, -28, 30)
```

---

## ٨. قواعد ثابتة

* **مباريات التحديد**: خمس مباريات بلا نقاط، ثمّ رتبة ابتدائية حسب عدد الانتصارات (البند ٥١).
* **حماية**: مباراة حماية واحدة بعد كل ترقية (البند ٥٠).
* **لا احتساب مرّتين**: كل مباراة بمعرّف فريد، وآخر ٢٤ معرّفًا محفوظة في الملفّ. النتيجة المكرّرة تُرفض بـ`applied:false` (البند ٩٩).
* **إعادة ضبط الموسم ليّنة**: نزول درجتين لا هبوط إلى برونزي (البند ٥٢).
* **موسم واحد عالمي** ورتبة مستقلّة لكل لعبة داخله (البند ٥٣).

---

## ٩. الربط — أين تُحسم كل مباراة

كل مباراة غرفة تنتهي برسالة واحدة (`end` أو `over`) يستقبلها `rmOn`، فتُسلَّم إلى `rmSettle`. هي التي تترجم نتيجة اللعبة إلى الشكل الذي يفهمه نموذج حسابها، ثمّ تنادي `resolveMatch`.

| اللعبة | مفتاح الغرفة | كيف تُعرف نتيجتي |
|---|---|---|
| كيرم | `carrom` | `by` هو الفائز. وفي أربعة لاعبين: لوني من `RM.ca.col` — **فوز الزميل فوزٌ لي** |
| أونو | `uno` | `rank` مرتّبة بعدد ما تبقّى في اليد، ومركزي منها |
| مافيا | `mafia` | `RM.role` يقرّر: `win==='mafia'` فوزٌ لي إن كنت مافيا، وخسارة إن كنت من الشعب |
| مسابقة الرسم | `draw` | مركزي من `rank` المرتّبة بالأصوات |
| برا السالفة | `barra` | إن كنت الجاسوس فزت بالنجاة، وإن كنت من المجموعة فزت بالإمساك به |
| عالم المعرفة | — | تمرّ مباشرةً على `resolveMatch` بمعرّف `M.mid` |

الوضع يُشتقّ من طريق الدخول:

```js
function rmMode(){
 if(RM.solo) return 'bot';        // ضدّ الكمبيوتر
 if(RM.mode) return RM.mode;      // 'casual' من البحث · 'room' من الغرفة
 return RM.code ? 'room' : 'casual';
}
```

ومعرّف المباراة يبثّه المضيف مع `start` فيتّفق عليه الجميع، فلا تُحتسب نتيجة مرّتين مهما تكرّر البثّ.

**`applyMatch` القديمة حُذفت** — صار `resolveMatch` المحرّك الوحيد لكل الألعاب.

---

## ١٠. ما ليس في هذه الطبقة

* **لا خادم.** البنود ٥ و٧٦ و٧٧ تفترض خادمًا يحفظ مؤشّر المهارة ويمنع الاستغلال ويقدّر زمن الانتظار. اللعبة اليوم بلا خادم، والحساب كلّه على الجهاز. النموذج مبنيّ بحيث ينتقل إلى الخادم بتغيير مصدر البيانات وحده، **ولا تدّعي الواجهة تحقّقًا لا يحدث**.
* **لا وضع مصنّف في الواجهة بعد.** كل مباريات اليوم تدخل بوضع `room` أو `bot` أو `casual`، فلا تمنح نقاط تصنيف. زرّ «لعب مصنّف» يأتي في المرحلة الخامسة، و`mmScr(g,'ranked')` جاهزة لاستقباله.
* **تمرير الجوال غير موصول عمدًا.** اللعب على جهاز واحد لا يُعرف فيه «أنا» من بين اللاعبين، فإسناد نتيجة شخصية إليه بلا معنى. ولو أردناه لاحقًا فهو إتقان فقط، لا نقاط.
* **لا تغيير مرئي.** قُورن نصّ إحدى عشرة شاشة بالإصدار السابق فجاء مطابقًا.
