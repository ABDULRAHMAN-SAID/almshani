## A. AUDIT للصفحتين

### A.1 صفحة «اللعب» — `playScr()` · السطر 17831

بنيتها الفعلية أربعة عناصر فقط:

```
simpleHead()      رأس: أفاتار · اسم · المستوى · عملتان
seasonHero()      البطاقة الكبرى: «الموسم 4 · أرشيف الزمن» + الرتبة + زر «العب»
battleChestRow()  أربع خانات صناديق
صفّان صغيران     تحديات اليوم · الموسم
```

**المقاسات المقيسة** (هاتف 430×950):

| القياس | القيمة |
|---|---|
| نهاية المحتوى | 541px |
| ارتفاع الشاشة | 950px |
| **فراغ غير مستغَل** | **409px = ٤٣٪ من الشاشة** |
| عدد بطاقات الألعاب | **صفر** |
| عرض القشرة على شاشة 1280 | 520px (مضبوط أصلًا) |

**العيوب المؤكَّدة:**

1. **`Gold II` بالإنجليزية** في قلب الصفحة — وهي ليست كلمة `Ranked` وحدها، بل **اسم الرتبة كامل** يأتي من `rankLabel()` التي تُعيد `t.n` الإنجليزي.
2. **لا توجد ولا لعبة واحدة على الصفحة.** الكيرم وأونو ومافيا والرسم وبرا السالفة غير موجودة إطلاقًا في «اللعب» — الوصول إليها فقط عبر «ليلة العائلة».
3. **زر «العب» لا يبدأ مباراة** — يدفع `playModesScr` (قائمة أوضاع وسيطة).
4. **البطاقة الكبرى تخلط ثلاثة أشياء**: الموسم + الرتبة + زر اللعب في صندوق واحد، فلا يُقرأ أيّها الأساس.
5. **٤٣٪ فراغ** تحته أشكال ثلاثية الأبعاد عائمة تملأ مكان المحتوى المفقود.
6. لا تسلسل أهمية: صناديق المعارك (ثانوية) تأخذ مساحة أكبر من أي لعبة.

### A.2 صفحة «ليلة العائلة» — `partyScr()` · السطر 19814

مبنيّة من جدول `PT_GAMES` (خمس ألعاب) — وهذه نقطة قوّة: الصفحة **مولَّدة من بيانات أصلًا**.

| القياس | القيمة |
|---|---|
| نهاية المحتوى | 718px من 950px |
| فراغ غير مستغَل | 232px = ٢٤٪ |
| بطاقات الألعاب | 5 |
| **الأقراص داخل البطاقات** | **15 قرصًا** (3 لكل بطاقة) |
| ارتفاع البطاقة | ~96px |

**العيوب المؤكَّدة:**

1. **كل بطاقة تحمل ٣ أقراص** (`📱 تمرير` · `🔗 كود` · `🌐 بحث` · `🤖 كمبيوتر`) — تمامًا ما وصفته في البند ٤٤: البطاقة تحاول تنفيذ كل إجراء بدل أن تختار اللعبة.
2. **لا رتبة ولا تقدّم لأي لعبة** — لأنّه لا يوجد تصنيف لهذه الألعاب أصلًا (انظر E).
3. الترتيب ثابت في المصفوفة: برا · مافيا · رسم · أونو · كيرم. لا «آخر لعبة» ولا مفضّلة.
4. البطاقات منخفضة والأيقونة 62px — أصغر من ٥٤–٦٤px المطلوبة مع وصف ورتبة.
5. شريط الوصف العلوي يشرح طرق اللعب — شرحٌ يصير بلا معنى بعد نقل الطرق إلى مركز اللعبة.

### A.3 مركز اللعبة — `gameHub(g)` · السطر 19910

يعرض أربع طرق: `مع الكمبيوتر` · `بحث عن لاعبين` · `غرفة بكود` · `تمرير الجوال`.

**العيب الجوهري: لا يوجد «لعب مصنف» ولا «لعب عادي» إطلاقًا.** كل مباراة في الكيرم أو أونو اليوم بلا تصنيف — لأنّ التصنيف غير موجود لها.

## C. تنفيذ التصنيف الحالي

### C.1 جدول الرتب — `TIERS` · السطر 13356

عشر رتب، لكلٍّ ثلاث درجات (عدا الأخيرة):

```js
{k:'bronze', n:'Bronze', ar:'برونزي', c:'#CD7F32', div:3, t:15, opt:[4,4]}
{k:'silver', n:'Silver', ar:'فضي',   …}
{k:'gold',   n:'Gold',   ar:'ذهبي',  …}
… platinum · diamond · master · grandmaster · champion · mythic · legend
const RP_PER_DIV = 100;
```

ملاحظتان:
* الحقل `t` و`opt` داخل جدول الرتب **يتحكّمان بزمن السؤال وعدد الخيارات** — أي أنّ جدول الرتب مربوط بقواعد لعبة المعرفة تحديدًا، فلا يصلح كما هو لستّ ألعاب.
* الأسماء العربية موجودة في `ar` لكنّها **غير مستعملة** في الشاشات.

### C.2 حالة اللاعب — `defaultRanked()` · السطر 13372

```js
{placed:false, placementDone:0, placementWins:0,
 tier:0, div:3, rp:0, mmr:1000, protect:0,
 seasonBest:{tier:0,div:3}, globalRank:null, wins:0, losses:0}
```

### C.3 المنطق القائم — وهو سليم ويستحقّ البقاء

| الدالة | ماذا تفعل | الحكم |
|---|---|---|
| `rpDelta(my,opp,won)` | ±17..27 / −12..−25 حسب فرق MMR | ✅ يطابق البند ٨ |
| `mmrDelta` | Elo بمعامل 32 | ✅ |
| `applyMatch(r,oppMmr,won)` | **يأخذ كائن الرتبة كوسيط** | ✅ مفتاح الترحيل |
| مباريات التحديد | 5 مباريات ثم رتبة ابتدائية | ✅ يطابق البند ٥١ |
| `protect` | حماية واحدة بعد الترقية | ✅ يطابق البند ٥٠ |
| `seasonBest` | أفضل رتبة في الموسم | ✅ يطابق البند ٩٥ |

**`applyMatch` تستقبل `r` كوسيط ولا تقرأ `S.ranked` داخلها** — أي أنّ المحرّك جاهز لتشغيله على أي عدد من الملفّات التنافسية. هذا يختصر الترحيل كثيرًا.

### C.4 عيوب يجب إصلاحها أثناء الترحيل

1. **رتبة عالمية ملفّقة**: `if(r.tier===9&&!r.globalRank) r.globalRank=12842;` (السطر 13479) — رقم مخترع يُعرض للاعب. يخالف البند ٧٥. يُحذف.
2. **سياسة أرقام مزدوجة**: `rankLabel` تستعمل `I · II · III` و`rankLabelAr` تستعمل `١ · ٢ · ٣`. البند ٦٥ يفرض سياسة واحدة (الأرقام الغربية).
3. `rankLabelAr` معرّفة ومستعملة **مرّتين فقط**، بينما `rankLabel` الإنجليزية مستعملة في **٨ مواضع**.

## D. أين كلمة Ranked وغيرها مكتوبة مباشرةً

فُحصت الشاشات بالعرض الفعلي في متصفّح ثمّ استُخرج النصّ المرئي — لا بالبحث في الشيفرة، حتى لا يختلط اسم متغيّر بنصّ مستخدم.

### D.1 النصّ الإنجليزي الظاهر فعلًا للاعب

| الشاشة | النصّ | المصدر |
|---|---|---|
| اللعب | `Gold II` | `rankLabel()` · 17885 |
| التصنيف | `Ranked` | `tb('Ranked',…)` · **16452** |
| التصنيف | `Gold II` | `rankLabel()` · 16456 |
| التصنيف | `RP` · `MMR` | نصّ مباشر في الشاشة |
| أوضاع اللعب | `Ranked` | `{k:'ranked', n:'Ranked', …}` · **18288** |
| أوضاع اللعب | `VS` | نصّ مباشر |
| المزيد | `Gold II` | `rankLabel()` |
| المتجر | `Season Pass` · `RP` | نصّ مباشر |
| المتجر | `Google Play` · `App Store` | **أسماء علامات — تبقى** (البند ١) |

### D.2 المواضع الأربعة لكلمة `Ranked` كنصّ مستخدم

```
16452   go(`… ${tb('Ranked',"tab('play')")}          ← عنوان شاشة التصنيف
17789   <button class="rbtn" onclick="rankedScr()"><span>Ranked</span></button>
17817   {k:'ranked', n:'Ranked', req:…, d:'اجمع 12 نجمة'}   ← اسم وضع مقفل
18288   {k:'ranked', n:'Ranked', d:'7 جولات · أنماط متغيرة'} ← بطاقة أوضاع اللعب
```

الخمسة عشر الباقية من أصل ١٩ تطابقًا هي `S.ranked` و`defaultRanked` و`startRanked` و`rankedScr` — **أسماء متغيّرات تبقى بالإنجليزية** (البند ٨٤).

### D.3 الأخطر من كلمة Ranked

`rankLabel(r)` تُعيد `Bronze/Silver/Gold/…` وتُستدعى في **٨ مواضع** (13429 · 13480 · 16424 · 16456 · 17771 · 17776 · 17885 · 18196). تعريب الكلمة الواحدة لا يكفي — لا بدّ من قلب دالة التسمية نفسها.

### D.4 النتيجة الطيّبة

«ليلة العائلة» ومراكز الألعاب والنادي والبطاقات **عربية بالكامل، صفر نصّ إنجليزي**. المشكلة محصورة في ثلاث شاشات: اللعب · التصنيف · أوضاع اللعب، وسطرين في المتجر.

## E. رتبة واحدة أم نموذج بيانات لكل لعبة؟

### **رتبة واحدة. للّعبة كلّها. قاطعًا.**

| الدليل | القيمة |
|---|---|
| كائنات الرتبة في الحالة | **1** — `S.ranked` |
| إشارات إلى `S.ranked` | 44 |
| مواضع منح التصنيف (`applyMatch`) | **2** — كلاهما داخل لعبة المعرفة |
| ألعاب لها تصنيف | **1** من 6 |

بالتفصيل:

* موضعا `applyMatch`: السطر **14438** (انسحاب من مباراة المعرفة) و**14944** (نهاية مباراة المعرفة).
* **الكيرم وأونو ومافيا والرسم وبرا السالفة لا تمنح ولا تخصم شيئًا.** لا RP ولا MMR ولا سجلّ فوز/خسارة. تنتهي المباراة (`rmSend({t:'end'})`) ولا تلمس الحالة التنافسية إطلاقًا.
* لا يوجد في الحالة أي مفتاح باسم لعبة: صفر تطابق لـ`S.carrom*` أو `S.uno*` أو `S.mafia*`…
* `S.stars` و`S.best` موجودان لكنّهما للشبكات والمحطّات، لا للتصنيف.

**فالبند ٢ ليس تعديلًا على نظام قائم — بل بناء نظام غير موجود.** خمس ألعاب من ستّ ستحصل على تصنيفها لأول مرّة.

### تنبيه واجب قبل البدء

البنود ٥ و٧٧ و٧٦ تفترض **خادمًا**: `hiddenMMR` عند الخادم، ومنع الاستغلال من جهته، وتقدير زمن الانتظار من مقاييسه. **اللعبة اليوم بلا خادم**: الحالة كلّها في `localStorage`، والغرف نظير-إلى-نظير عبر قدرة الغرفة في الـArtifact، والخصوم في مباريات المعرفة محاكون على الجهاز.

ما سأبنيه الآن هو **النموذج والواجهة والقواعد كاملةً على الجهاز**، بحيث ينتقل الحساب إلى الخادم لاحقًا بتغيير مصدر البيانات وحده. ولن أكتب في الواجهة أنّ الخادم يتحقّق ما دام لا يفعل — كما التزمنا في النادي.

## F. خطة ترحيل `GameRankProfile`

### F.1 النموذج (البند ٦٨)

```js
GAMES = ['knowledge','carrom','uno','mafia','drawing','outsider']   // معرّفات إنجليزية · البند ٦٩

GameRankProfile = {
  gameId, seasonId,
  visibleTier, division, rankPoints,      // ما يراه اللاعب
  hiddenMMR,                              // لا يُعرض
  peakTier, peakDivision,
  wins, losses, gamesPlayed, winStreak,
  placementMatchesRemaining,              // 5 → 0
  masteryXp, masteryLevel,                // منفصل عن الرتبة · البند ٥٧
  lastPlayedAt
}

S.gameRanks = { knowledge:{…}, carrom:{…}, uno:{…}, mafia:{…}, drawing:{…}, outsider:{…} }
```

### F.2 الترحيل من الحالة القديمة — بلا فقدان

```js
function migrateRanks(){
  if(S.gameRanks) return;
  S.gameRanks = {};
  for(const id of GAMES) S.gameRanks[id] = newRankProfile(id);
  if(S.ranked){                                  // رتبة اليوم كانت رتبة المعرفة فعليًّا
    S.gameRanks.knowledge = fromLegacy(S.ranked);
  }
  S.rankedLegacy = S.ranked;                     // تبقى نسخة حتى نتأكّد ثمّ تُحذف في إصدار لاحق
}
```

رتبة اللاعب الحالية **تنتقل كما هي إلى المعرفة**، وباقي الألعاب تبدأ **«غير مصنّف»** لا برونزي (البند ٩٢).

### F.3 جداول مقودة بالبيانات (البنود ٧٠ · ٧١)

```js
RANK_TIERS = [ {id:'bronze', ar:'برونزي', divisions:3, color, badge},
               …, {id:'legend', ar:'أسطوري', divisions:3},
               {id:'apex', ar:'قمة الأساطير', divisions:0} ]

GAME_DEFS = [ {id:'carrom', ar:'كيرم', icon, desc,
               rankedEnabled:true, casualEnabled:true, privateRoomEnabled:true, botEnabled:true,
               minPlayers:2, maxPlayers:4, scoreModel:'winLoss', status:'live'}, … ]
```

* أسماء الرتب المطلوبة في البند ٤ (برونزي… أسطوري ثمّ قمة الأساطير) تُكتب في `RANK_TIERS` وحده.
* `t` و`opt` (زمن السؤال وعدد الخيارات) **تخرج من جدول الرتب** إلى إعداد خاصّ بلعبة المعرفة، لأنّها ليست خاصيّة رتبة بل خاصيّة لعبة.

### F.4 نماذج الحساب لكل لعبة (البنود ٧–١٣)

| اللعبة | `scoreModel` | الأساس |
|---|---|---|
| knowledge | `winLoss` | فوز/خسارة + MMR الخصم. الإجابات الصحيحة **فاصل تعادل فقط** |
| carrom | `winLoss` | فوز/خسارة + MMR. الدقّة والأخطاء والملكة **إحصاءات ملفّ لا RP** |
| uno | `placement` | 1v1: فوز/خسارة · 4 لاعبين: ترتيب (+كبير/+صغير/−صغير/−أكبر) معدّلًا بالـMMR |
| mafia | `teamResult` | نتيجة الفريق + إكمال المباراة + معدّل الانسحاب. **بلا أي تقييم للكلام** |
| outsider | `roundsAggregate` | تُجمع الجولات ثمّ نتيجة واحدة للمباراة |
| drawing | `placement` | الترتيب + التخمينات الناجحة + نجاح الآخرين في تخمين رسمك |

كلّها تمرّ عبر واجهة واحدة:

```js
resolveMatch({gameId, mode, result, opponents}) → {rpDelta, mmrDelta, events:[…]}
```

### F.5 قواعد ثابتة تُفرض في مكان واحد (البنود ١٥ · ٧٧ · ٩٩)

```js
function grantsRP(mode){ return mode === 'ranked' }   // النقطة الوحيدة في المشروع
```

`room` · `friendly` · `bot` · `casual` · `pass` ⟶ **لا RP إطلاقًا**، وتُمنَح `masteryXp` بسيطة بدلها.
وتُختم كل مباراة بمعرّف `matchId` فريد يُسجَّل، فلا تُحتسب نتيجة مرّتين (البند ٩٩).

### F.6 الموسم (البنود ٥٢ · ٥٣)

موسم واحد عالمي `seasonId`، ورتبة مستقلّة لكل لعبة داخله. وإعادة الضبط **ليّنة**: كل لعبة تنزل درجتين لا إلى برونزي.
